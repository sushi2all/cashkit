## Pen quirks hit (this build, 2026-09-26)

- **Globals do not persist** between `execute` calls (contrary to the skill text). Use the literal ids in this file.
- **`height:"$control-h"` / `width:"$var"` are silently dropped** from the node. Sizes must be numbers; variables work for fill, stroke, cornerRadius, gap, padding, fontFamily, letterSpacing.
- **`fontWeight:600` (number) is silently dropped**; use the string `"600"` / `"500"`.
- **Nested `descendants:{}` inside a descendant override is ignored**. Use slash paths: `"Row Status/Badge Text"` (names) or `"pfI3K/bZcED"` (ids). Both tested.
- **`Update(ref,{descendants:{…}})` replaces the whole override map** as far as tested: always pass the full map for that instance.
- **`Move` keeps ids**: regrouping the Nav Item's children into `Nav Left` / `Nav Right` left every instance override (`fkZQt`, `oq178`, `Z4xrS/bZcED`, `YyvNS`) working.
- **A fit_content frame whose first child is an icon and second a text reported width = the icon's width** (`Nav Left`: 16 px with a 56 px label at x 24, height correct at 17), so the label was flagged "fully clipped" on the master; a gap toggle, an explicit `layout:"horizontal"` and a font-weight change did not move it. `width:"fill_container"` on that frame (root is fill-width, so no circularity) fixed the report without a visual change. Setting a default value (`layout:"horizontal"`, `gap` back to 8) is dropped silently.
- **`execute` with `edits` still needs `filePath`**: an edits-only retry without it fails input validation.
- **Disabled nodes still report `ctx.problems`** ("partially/fully clipped") with pre-layout bounds. Filter with `n.enabled!==false`; with that filter the library reports zero problems (re-verified 2026-09-26 after the rail rebuild).
- **Bounds read in the same call as the inserts or updates can be stale** (everything reports "fully clipped", or old positions). Re-run the check in the next call.
- A child with `height:"fill_container"` inside a fit_content parent resolves correctly but raises the "circular" warning; fixed heights were used instead.
- `Copy` of a frame that contains refs: `descendants` keys use the ORIGINAL nested ids (`"fVkQS/qfAmL"`) and are remapped; the copy's direct children get new ids (read with `Get(copy,{depth:2})`).
- Per-side strokes (`strokeWidth:{bottom:1}`) and `strokeAlignment:"inner"` work as documented. Every control box uses inner alignment so the stated sizes are outer sizes.
- All icon names used (`layout-dashboard square-check table-2 receipt git-compare git-branch history settings circle-alert circle-user book chevron-down command bell x search crosshair git-fork calendar-check plus circle-question-mark building briefcase`) rendered; none rejected. `check-square` (REQUIREMENTS §3.2 spelling) is not in lucide-valid.txt.
- `TakeScreenshot` downsamples 1232 px wide nodes to ~400 px: screenshot the sub-frame you need to check.
- Text widths at these sizes (for fitting copy without a measure pass): Plex Mono 11 ≈ 6.6 px/char (+1.2 tracking for stamps ≈ 8.25), Mono 12 ≈ 7.2, Mono 13 ≈ 7.8, Mono 32 ≈ 18.7; Plex Sans 13/500 ≈ 6.3, Sans 11/600 +1.2 ≈ 7.3.
