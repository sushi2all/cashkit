CashKit · the toolkit under the hood

The SDK, under the hood

One object to hold a plan, one way to change it, one calculator, three places data lives. Every change answers with a report of what moved, and anything that goes wrong comes back as a message with a suggested fix, never a crash.

Time is built inEvery value is a whole row of numbers, one per day or month, across the planning horizon. Only prev() looks back at the previous period.
Results can be reproducedA calculation is fully described by which saved version, which scenario, which calculator version and how much of the ledger it saw. Nothing looks at today's date.
Numbers explain themselvestrace() shows the formula, the values that went into it and the arithmetic. why_zero() says why a cell is empty.

The big picture PRD §3.1

Callers talk to one toolkit. The toolkit talks to everything else.

Two copies of the plan exist. The kit holds the one you wrote. The calculator adds a few helper items of its own (for tax and for stray ledger rows) that never leave a calculation. An old saved version is read-only by construction (ADR-0033): it simply has no methods that change anything.

create_book
creates the folder layout on disk, looks up the public holidays once and stores them with the plan so results never change when the holiday list does
set_item / set_param
one call per kind of thing, with the scenario as an argument; a formula is checked the moment you write it, and the change is on disk before the call returns
validate
the same list of problems a calculation reports, sorted with errors first; there is only one place that decides what is wrong
run
work out what this scenario's plan is, pick up the ledger rows it can see, calculate, hand back a result you can question
commit
take the lock, recalculate every scenario, store the headline numbers next to the plan, save a version

def set_item(self, item, *, scenario="base") -> ChangeReport:
    if scenario not in self.state.scenarios: return CK-E021
    refusing = isolated_problems(item)         # E003 formula won't parse
    if refusing:                               # E004/E005 settlement can't mean anything
        return ChangeReport(diagnostics=refusing)   # E011 sign vs direction · E012 stock

    before = self.resolve(scenario).book
    report = self.state.set_item(scenario, item)    # base → authored book
    if report.empty: return report                  # other → field-sparse overlay
    reporting = compile_book(self.resolve(scenario).book).diagnostics \
              - compile_book(before).diagnostics    # only the NEW problems:
    self._save()                                    # E001 unknown ref · E002 cycle
    return report + reporting                       # E008 unknown param · E020

Every change goes through one gate, which owns the plan and its scenarios, and every change that recorded something is on disk before the call returns. The caller uses the same method whether the target is the main plan or a scenario.

Calculating CashKit.run

run() is four lines. Everything that makes the result repeatable happens before it.

def run(self, scenario="base", *, cutover_override=None) -> RunRef:
    resolution = self.resolve(scenario)                   # chain → Book + diagnostics
    book = resolution.book
    if cutover_override is not None:                      # a query, not a model change:
        book = book.copy(cutover=cutover_override)        # never cached, never snapshotted

    events, event_diags = self.events_for(scenario)       # ledger view for this scenario
    engine = Engine(book, self.policy, events)            # compile: facts ∪ graph ∪ SCC
    result = engine.run()                                 # int64 columns

    return RunRef(scenario, book, result, engine, kit=self,
                  revision=self.revision, policy=self.policy,
                  diags=resolution.diags + event_diags + result.diags)

def validate(self, scenario="base") -> list[Diagnostic]:
    return ordered(self.run(scenario).diagnostics)        # one source of truth

def events_for(self, scenario):
    watermark = self.book.ledger_watermark if self.revision else None
    #           ↑ at(ref) truncates the ledger; a live kit sees all of it
    return self.state.resolve_events(scenario, self.ledger.facts(watermark))

Inside the calculator cashkit/engine/run.py

Prepare once: merge plan and ledger, check every formula, work out the order. Then compute, each item after the ones it needs.

Inside the calculator PRD §5.1

Everything is computed a whole row at a time, except the few items that feed back into themselves

def _evaluate(self, stale: set[ItemId]) -> RunResult:
    for item in stale: zero its columns, drop its diagnostics

    for item in generative ∩ stale:               # 1. expansion
        accrual[item], cash[item] = expand_item(item, cutover, policy)
    self._apply_event_facts(stale)                # 1b. ledger union

    for component in self.compiled.components:    # 2. topological order
        if no member in stale: continue           #    delta reuses columns
        if component.trivial:
            expr = compiled[member].expr
            accrual[member] = ColumnEvaluator(window).eval(expr)  # T at once
            settle_occurrences(member, accrual[member] → cash[member])
        else:
            cells = [compile_cell(expr, window, policy) for m in members]
            for t in range(T):                    # the ONE python loop
                for cell, m in cells:
                    accrual[m][t], zero_div = cell(t)
                    plan.apply(t, value → cash[m])   # legs at fixed offsets

    return RunResult(accrual, cash, vat, diagnostics)

def delta(self, changed: dict[ItemId, Item]) -> RunResult:
    recompile; moved = items whose expr or deps changed
    return self._evaluate(self.compiled.downstream(moved))  # cone only

How money is handled PRD §5.3 · ADR-0002 · ADR-0003

Money is whole numbers of ten-thousandths. Rounding happens in one fixed order, and two independent calculators must agree to the last digit.

The formula language PRD §5.4

A small, closed language. where instead of if, so both branches are always computed.

it("acme_impl")another item's value in this period (its cash, unless told otherwise)
prev("cash", n=1, init=…)the value n periods ago. The only way to look back; init is the starting value
p.vat_standarda named parameter, kept exact
agg(tag="cat:revenue")the total of every item matching a tag, decided before computing starts
cum("revenue")running total from the start of the horizon
t.index · t.month · t.is_quarter_endfacts about the period itself
where(cond, a, b)pick a or b per period, both are always computed
min max clip round_ abs_the complete list of built-in functions
a / xdividing by zero gives 0 and a warning (CK-W005), but only if that value was actually used
parse_formula(src) -> ParseOutcome(expr | diagnostic)
    ast.parse(src)             # bounded: len ≤ 4096, depth ≤ 40, |literal| ≤ 9e14
    _Translator.visit(node)    # whitelist == translator: legal iff a visit_ exists
    Literal | Param | TimeField | ItemRef | Prev | Agg | Cum
    | Unary | Binary | Compare | Logical | Where | Builtin
    # no eval · no attribute access beyond p./t. · no other calls → CK-E003

value kinds, fixed by node type (never by runtime value):
    rate  = exact Fraction        Literal, Param, rate∘rate
    money = int64 @ 4dp           it, prev, agg, cum, where, builtins
    mask  = bool                  Compare, Logical, t.is_*

ColumnEvaluator(window, policy).eval(expr)      # trivial tier
    kernel = ArrayKernel      # numpy int64 columns over the horizon
compile_cell(expr, window, policy) -> fn(t)     # fold tier
    kernel = ScalarKernel     # Python ints; rates folded to constants at compile
    # same dispatch, same promotion, same rounding boundaries — once

Scenarios cashkit/sdk/scenarios.py · ADR-0007 · ADR-0009

A scenario stores only what it changed. Everything else comes from its parent. A schedule is always replaced whole.

def _resolve_chain(self, chain) -> Resolution:
    items  = dict(self.book.items)
    params = dict(self.book.params)
    origins = {id: {f: FieldOrigin("book")} for id in items}

    for scenario in chain:               # root first
        for id in scenario.removed:
            items.pop(id); removed_by[id] = scenario.id
        for id, item in scenario.added:  items[id] = item
        for id, overlay in scenario.items:
            if id not in items:  CK-E023; continue
            items[id] = _apply_overlay(items[id], overlay)
            for f in overlay.model_fields_set:   # recorded fields only
                origins[id][f] = FieldOrigin(scenario.id)
        params.update(scenario.params)
        merge event_overrides field-sparse too

    if "opening_balance" in params:      # reserved: capital injection
        opening = require_money(params[...]) or CK-E024

    return Resolution(self.book.copy(items, params, opening),
                      origins, removed_by, event_overlays, diags)

Saving and history CashKit.commit · at · reproduce · ADR-0018

commit() saves the plan together with its headline numbers. at() reopens an old version as a working kit.

def commit(self, message, *, scenarios=None, author="agent") -> CommitReport:
    with WriterLock(self.root) as lock:              # O_EXCL .cashkit/lock
        if not lock.acquired: return CK-E013 (holder pid, since)
        watermark = self.ledger.watermark()          # stamped HERE only
        for sid in scenarios or all:
            run = self.run(sid)
            self.summaries[sid] = CommittedSummary(  # snapshots/<sid>.summary.yaml
                ENGINE_VERSION, watermark, run.summary())
        state = build_state(self.config_state(watermark_from_ledger=True))
        write_working_tree(self.root, state)         # canonical YAML, file per item
        revision = self.revisions.write_revision(state, message, author,
            metadata={"engine-version", "schema-version", "watermark"})
    return CommitReport(revision)                    # revision=None + CK-I002 if unchanged

def at(self, ref) -> (ReadOnlyKit | None, diagnostics):  # "HEAD" · "HEAD~n" · id
    revision = self.revisions.resolve(ref)  or CK-E027
    config   = load_state(self.revisions.read_state(revision))   # migrated forward
    return ReadOnlyKit(root, ScenarioSet(config.book, config.scenarios),
                       revisions=self.revisions, ledger=self.ledger,  # same stores
                       settings=config.settings, revision=revision.id) # ledger truncated

kit.at("HEAD~5").run("downside").summary()   # eras compare through one API
kit.at("HEAD~5").set_item(...)               # AttributeError: the past has no writes

Any change to the calculator that could move a number also bumps its version number, in the same commit. This is a rule people follow, not something the code enforces. Whether an old result still reproduces is checked, never assumed (ADR-0006).

Problems are answers, not crashes PRD §6.5 · §10.1

One shape for every problem, one numbered catalogue, and each problem comes from exactly one place.

class Diagnostic(CashKitModel):
    severity: "error" | "warning" | "info"
    code: "CK-[EWI]ddd"
    item_id: ItemId | None
    field: str | None
    message: str
    suggested_fix: str        # never empty

class ChangeReport:
    target: str
    changed: (field, …)       # what ACTUALLY moved
    created: (id, …)
    diagnostics: (…)
    ok = no error-severity

A caller can act on a code and a suggested fix; it cannot act on a crash. Crashes are kept for genuine programming mistakes, such as passing the wrong type. Trying to change an old version is not even a code: the read-only kit has no method for it.

class RevisionStore(Protocol):            # git_store.py is ONE implementation
    write_revision(state, message, author, metadata) -> Revision | None
    head() · resolve(ref) · list_revisions(limit, path)
    read_state(ref) -> RevisionState · diff_revisions(a, b) -> StateDiff
    # linear history: no branch, no merge. refs: HEAD · HEAD~n · id

class LedgerStore(Protocol):              # SqliteLedger
    add_event · import_events · void_event · correct_event
    query_events · facts(watermark) · watermark()

class FrameStore(Protocol):               # DuckdbFrameStore
    materialize(run_id, result, book) · frame · pivot · compare · export

Every change is on disk before the call returns (ADR-0031): what is in the folder is what the kit holds, and only commit() turns it into a saved version. Each storage technology is used in one file: git, SQLite and DuckDB each have theirs, and a test checks that stays true. The clock is read in one file only, to timestamp saves and locks, and the calculator can never reach it.

The safety rails ADR-0010 · ADR-0016 · tests/

What keeps a number from being quietly wrong

No floating point near moneyA test audits every type; money refuses to be built from a float; yearly increase factors are computed exactly (ADR-0002).
The calculator never looks at the clockA test forbids any call that reads today's date. The cutover is set by you, and public holidays are stored with the plan.
Two calculators must agreeThe fast one and a deliberately simple one are compared cell by cell on a fixed set of plans, on every test run, and must match exactly.
Both sides of a choice are always computedwhere, never if, so a formula cannot hide an error in the branch that was not taken.
One writer at a timeOne lock covers all three stores. A second writer is told no (CK-E013); two sets of changes are never merged quietly.
Files are always written the same waySaving the same plan twice gives identical bytes, so a version difference always means a real change.
No AI inside the calculatorA test checks for it. The calculator knows nothing about any country's taxes; that knowledge and the AI agent live in the app on top (ADR-0021).
Say so rather than guessAdding up two currencies is refused. An actual after the cutover is flagged. A broken formula zeroes one item, never the whole result.
