Construction cashkit/sdk/construction.py

Two tiers at write time: refuse what is wrong alone, record what the book may fix later

def _admit(kit, item) -> ItemRef:
    refusing = _isolated_problems(item)        # E003 formula won't parse
    if refusing:                               # E004/E005 settlement can't mean anything
        return ItemRef(diagnostics=refusing)   # E011 sign contradicts direction
                                               # E012 generative stock
    candidate = kit.book + {item.id: item}
    reporting = compile_book(candidate).diagnostics \
              - compile_book(kit.book).diagnostics   # only the NEW problems:
                                               # E001 unknown ref · E002 cycle
    report = _write_item(kit, item)            # E008 unknown param · E020
    kit.save()                                 # working tree on disk, not a revision
    return report + reporting

def _write_item(kit, item) -> ItemRef:
    existing = kit.book.items.get(item.id)
    if existing == item:  return ItemRef(CK-I002)   # nothing moved: say so
    kit.scenarios.set_book(items={**kit.book.items, item.id: item})
    return ItemRef(created=(id,)) if existing is None \
      else ItemRef(changed=fields_that_differ(existing, item))

Every write goes through ScenarioSet, the one owner of the authored book. Construction writes base's content (top-level files); scenario verbs write overlays. Same path, other half.

Execution CashKit.run

run() is four lines. Everything deterministic is upstream of it.

def run(self, scenario_id="base", *, cutover_override=None) -> RunRef:
    resolution = self.scenarios.resolution(scenario_id)   # chain → concrete Book
    book = resolution.book
    if cutover_override is not None:                      # a query, not a model change:
        book = book.copy(cutover=cutover_override)        # never cached, never snapshotted

    events, event_diags = self.events_for(scenario_id)    # ledger view for this scenario
    engine = Engine(book, self.policy, events)            # compile: facts ∪ graph ∪ SCC
    result = engine.run()                                 # int64 columns

    return RunRef(scenario_id, book, result, engine,
                  revision=self.bound_to, policy=self.policy,
                  diags=resolution.diags + event_diags + result.diags)

def events_for(self, scenario_id):
    watermark = self.book.ledger_watermark if self.bound_to else None
    #           ↑ at(ref) truncates the ledger; a live kit sees all of it
    facts = self.ledger.facts(watermark)
    return self.scenarios.resolve_events(scenario_id, facts)

Engine PRD §5.1 · two-tier evaluation

Everything is a column, except the feedback set

def _evaluate(self, stale: set[ItemId]) -> RunResult:
    for item in stale: zero its columns, drop its diagnostics

    for item in generative ∩ stale:               # 1. expansion
        accrual[item], cash[item] = expand_item(item, cutover, policy)
    self._apply_event_facts(stale)                # 1b. ledger union

    for component in self.compiled.components:    # 2. topological order
        if no member in stale: continue           #    delta reuses columns
        if component.trivial:
            expr = compiled[member].expr
            accrual[member] = ColumnEvaluator(window).eval(expr)  # T at once
            settle_occurrences(member, accrual[member] → cash[member])
        else:
            cells = [compile_cell(expr, window, policy) for m in members]
            for t in range(T):                    # the ONE python loop
                for cell, m in cells:
                    accrual[m][t], zero_div = cell(t)
                    plan.apply(t, value → cash[m])   # legs at fixed offsets

    return RunResult(accrual, cash, vat, diagnostics)

def delta(self, changed: dict[ItemId, Item]) -> RunResult:
    recompile; moved = items whose expr or deps changed
    return self._evaluate(self.compiled.downstream(moved))  # cone only

Formula language PRD §5.4 · cashkit/engine/formula.py · columns.py · fold.py

where, not if. A closed AST, evaluated by one evaluator with two kernels.

it("acme_impl")another item, this period (cash by default)
prev("cash", n=1, init=…)n periods back. The only cycle-breaker; init seeds t < n
p.vat_standardnamed param, an exact rate
agg(tag="cat:revenue")sum over a selector, resolved to ids at compile
cum("revenue")running total since horizon start
t.index · t.month · t.is_quarter_endperiod metadata columns
where(cond, a, b)elementwise select, both branches evaluate
min max clip round_ abs_the whole builtin table
a / xmasked-safe: 0 at x==0, CK-W005 only if selected
parse_formula(src) -> ParseOutcome(expr | diagnostic)
    ast.parse(src)             # bounded: len ≤ 4096, depth ≤ 40, |literal| ≤ 9e14
    _Translator.visit(node)    # whitelist == translator: legal iff a visit_ exists
    Literal | Param | TimeField | ItemRef | Prev | Agg | Cum
    | Unary | Binary | Compare | Logical | Where | Builtin
    # no eval · no attribute access beyond p./t. · no other calls → CK-E003

value kinds, fixed by node type (never by runtime value):
    rate  = exact Fraction        Literal, Param, rate∘rate
    money = int64 @ 4dp           it, prev, agg, cum, where, builtins
    mask  = bool                  Compare, Logical, t.is_*

ColumnEvaluator(window, policy).eval(expr)      # trivial tier
    kernel = ArrayKernel      # numpy int64 columns over the horizon
compile_cell(expr, window, policy) -> fn(t)     # fold tier
    kernel = ScalarKernel     # Python ints; rates folded to constants at compile
    # same dispatch, same promotion, same rounding boundaries — once

Scenarios cashkit/sdk/scenarios.py · ADR-0007 · ADR-0009

Field-sparse overlays resolve along the parent chain. segments is atomic.

def _resolve_chain(self, chain) -> Resolution:
    items  = dict(self.book.items)
    params = dict(self.book.params)
    origins = {id: {f: FieldOrigin("book")} for id in items}

    for scenario in chain:               # root first
        for id in scenario.removed:
            items.pop(id); removed_by[id] = scenario.id
        for id, item in scenario.added:  items[id] = item
        for id, overlay in scenario.items:
            if id not in items:  CK-E023; continue
            items[id] = _apply_overlay(items[id], overlay)
            for f in overlay.model_fields_set:   # recorded fields only
                origins[id][f] = FieldOrigin(scenario.id)
        params.update(scenario.params)
        merge event_overrides field-sparse too

    if "opening_balance" in params:      # reserved: capital injection
        opening = require_money(params[...]) or CK-E024

    return Resolution(self.book.copy(items, params, opening),
                      origins, removed_by, event_overlays, diags)

Version control CashKit.commit · at · reproduce · ADR-0018

commit() snapshots outcomes with config. at(ref) returns a kit, not a book.

def commit(self, message, *, scenarios=None, author="agent") -> CommitReport:
    if self.bound_to: return CK-E030                 # a past kit is read-only
    with WriterLock(self.root) as lock:              # O_EXCL .cashkit/lock
        if not lock.acquired: return CK-E013 (holder pid, since)
        watermark = self.ledger.watermark()          # stamped HERE only
        for sid in scenarios or all:
            run = self.run(sid)
            self.summaries[sid] = CommittedSummary(  # snapshots/<sid>.summary.yaml
                ENGINE_VERSION, watermark, run.summary())
        state = build_state(self.config_state(watermark_from_ledger=True))
        write_working_tree(self.root, state)         # canonical YAML, file per item
        revision = self.revisions.write_revision(state, message, author,
            metadata={"engine-version", "schema-version", "watermark"})
    return CommitReport(revision)                    # revision=None + CK-I002 if unchanged

def at(self, ref) -> (CashKit | None, diagnostics):  # "HEAD" · "HEAD~n" · id
    revision = self.revisions.resolve(ref)  or CK-E027
    config   = load_state(self.revisions.read_state(revision))   # migrated forward
    return CashKit(root, ScenarioSet(config.book, config.scenarios),
                   revisions=self.revisions, ledger=self.ledger,  # same stores
                   settings=config.settings, bound_to=revision.id) # ledger truncated

kit.at("HEAD~5").run("downside").summary()   # eras compare through one API

Any engine change that can move a number bumps ENGINE_VERSION in the same commit. Nothing enforces it mechanically. Reproduction is checked, never assumed (ADR-0006).

class RevisionStore(Protocol):            # git_store.py is ONE implementation
    write_revision(state, message, author, metadata) -> Revision | None
    head() · resolve(ref) · list_revisions(limit, path)
    read_state(ref) -> RevisionState · diff_revisions(a, b) -> StateDiff
    # linear history: no branch, no merge. refs: HEAD · HEAD~n · id

class LedgerStore(Protocol):              # SqliteLedger
    add_event · import_events · void_event · correct_event
    query_events · facts(watermark) · watermark()

class FrameStore(Protocol):               # DuckdbFrameStore
    materialize(run_id, result, book) · frame · pivot · compare · export

One driver import per module: pygit2 in git_store.py, sqlite3 in ledger.py, duckdb in frames.py. A structural test greps the package. The wall clock is read in stores/clock.py alone, for commit and lock timestamps, unreachable from engine or model.

Determinism guards ADR-0010 · ADR-0016 · tests/

What keeps a number from being silently wrong

No float in money pathsType-audit test; Money validator rejects float; escalation factors in Decimal (ADR-0002).
No wall clock in engine/ or model/Lint test bans today(), now(), time.time(). Cutover is authored; holidays are snapshotted into the book.
Dual-engine gateVectorized int64 engine vs naive Decimal oracle: exact integer equality on every cell of a deterministic corpus, every test run.
Both branches always evaluatewhere, never if. Proved structurally: the whitelist is the translator.
Single writerOne lock across all three stores. A second writer gets CK-E013; nothing ever merges silently.
Canonical serializationByte-stable YAML; a phantom diff is a build failure. Semantic diffs compare models, not bytes.
No LLM under cashkit/Test asserts no model dependency. The engine is content-free: tax mechanics and the agent are app-layer (ADR-0021).
Diagnostic over guessCross-currency agg() refuses. Actual after cutover warns. Broken formula zeroes one line, never the run.
